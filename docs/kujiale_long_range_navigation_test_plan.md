> 实施分支：`codex/kujiale-long-route-redesign`（基于 `codex/kujiale-long-range-navigation-test`）
>
> 文档状态：路线与障碍已重设计；仅完成配置契约和地图示意核验，尚未执行新的 Pilot 或 20+20 正式验收。
>
> 适用场景：`kujiale_0026_A_to_B_door_open.usd`

## 1. 实验目标与固定条件

在固定场景、地图、起点和路线下完成可复现的正式验收：

- 场景：`kujiale_0026_A_to_B_door_open.usd`；
- 地图：`warehouse_new`；
- 起点：`long_route_start_g1`，Map 位姿 `[0.45, -5.35, 90 deg]`；它由 `mapping_start` 的已标定 Map-to-USD 变换派生并自动核验；
- 定位：Ideal Odometry / Ideal Localization；
- 导航配置：`rgbd_navigation`；
- 仿真：`physics_dt=1/60 s`、`RTF=1.0`；
- 静态避障：20 次，严格成功率和物理无碰撞率均须达到 `19/20=95%`；
- 动态避障：20 次，严格成功率和物理无碰撞率均须达到 `18/20=90%`；
- 每轮执行同一条从 G1 出发、覆盖主要房间并回到 G1 的闭环长路线；
- 每个成功静态实验的 Ground Truth 实际路线相对理论最优路线偏差均须不高于 `20%`；
- `/plan`、`/optimal_trajectory` 和 `/transformed_global_plan` 用于规划与跟踪诊断，不代替 Ground Truth 正式验收。

`ros2_ws/src/robot_description/rviz/navigation.rviz` 的导航视角配置与本方案一并纳入版本控制。正式报告记录 Git HEAD、工作区差异摘要以及所有配置和地图哈希。

## 2. 全屋闭环路线

每轮包含连续 5 个 `NavigateToPose` 动作，中途不重置机器人。G1 同时是出生点和最终回归点；原狭窄通道航点已移除，原左侧厕所和左下房间航点依次重命名为 G4、G5。所有房间航点采用相同的显示方式、成功条件和统计口径。

| 顺序 | 区域 | Map 目标 `[x, y, yaw]` | 栅格净空约值 |
| --- | --- | --- | ---: |
| S / G1 | 最下方房间；出生点 | `[0.45, -5.35, 90 deg]` | 0.60 m |
| G2 | 上方大房间 | `[0.80, 4.80, -160 deg]` | 0.90 m |
| G3 | 左上房间出口侧 | `[-2.55, 3.65, -100 deg]` | 0.47 m |
| G4 | 左侧厕所 | `[-3.25, -0.45, -75 deg]` | 0.55 m |
| G5 | 左下房间 | `[-2.50, -3.35, -35 deg]` | 0.46 m |
| G1 | 最下方房间；闭环回归点 | `[0.45, -5.35, 90 deg]` | 0.60 m |

原狭窄通道中的中间停靠点已删除，避免在有限净空内完成无意义的到点—转向动作。G3 直接连到原左侧厕所航点（现 G4），再到左下房间航点（现 G5）并回归 G1。中间航点朝向面向下一段：G3 为 `-100°`、G4 为 `-75°`、G5 为 `-35°`；这样让到点后的 MPPI 能直接建立下一段朝向。G4 仅作为普通房间航点显示和统计，不使用厕所专属样式。

路线控制使用固定噪声 MPPI（`vx_std=0.35`、`wz_std=0.75`、`wz_max=1.35 rad/s`），并把 GoalAngleCritic 的预对准距离设为 `1.0 m`，以在中间目标完成前开始建立下一段朝向。局部/全局 Costmap 的真实 footprint 碰撞检查、`0.40 m` inflation 半径和 Collision Monitor 的 `StopZone` 均不变；仅将软代价梯度设为 `cost_scaling_factor=9.0`、CostCritic 权重设为 `1.35`，让低矮方块绕行选择连续轨迹而非爬行/重采样。SlowdownZone 横向半宽从 `0.235 m` 收紧到 `0.232 m`、触发点从 5 提高到 6，避免有效平行墙回波反复造成爬行/停车。

统一航点条件：

- 位置误差不高于 `0.25 m`；
- 朝向误差不高于 `10 deg`；
- 每段 Nav2 Action 必须返回 `SUCCEEDED`；
- 单段超时：静态 `180 s`、动态 `210 s`；
- 整轮超时：静态 `600 s`、动态 `720 s`；
- 最终静止时间不少于 `1 s`；
- 最终线速度不高于 `0.02 m/s`、角速度不高于 `0.05 rad/s`；
- 闭环 GT 实际里程不少于 `20 m`。

G2 已由房间内部移至出口侧，减少到达后为下一段掉头的需求。当前可微调基线已有同步的 footprint-aware SE(2)
候选理论参考由当前五目标路线和可编辑障碍基线自动生成；它不构成正式冻结。最终批次前必须在确认布局后重新运行参考生成器。

## 3. 障碍物与正式实验矩阵

### 3.1 静态场景

未来静态批次使用中心区六组低矮实体障碍：四个方块和两个长条；它们远离 G1 出生点，车辆在向 G2 行驶的过程中才进入其影响范围。
当前位置是供 Isaac GUI 反复拖动和 RViz 手动导航观察的临时种子，尚未冻结为正式批次参数：

- ID：`rgbd_low_box_west`、`rgbd_low_box_center`、`rgbd_low_box_east`、`rgbd_low_box_north`、`rgbd_low_bar_east`、`rgbd_low_bar_north`；
- 当前可微调 Map 基线由 GUI 于 `2026-07-23 13:37:02 +08:00` 完整导出：`rgbd_low_bar_east=[1.286899, 0.033996, 0.08]`、`rgbd_low_bar_north=[-0.703143, 0.252652, 0.08]`、`rgbd_low_box_center=[-2.135744, -0.876959, 0.08]`、`rgbd_low_box_east=[0.366563, 0.66795, 0.08]`、`rgbd_low_box_north=[0.126442, -0.579985, 0.08]`、`rgbd_low_box_west=[-0.853013, -0.961904, 0.08]`；快照为 `isaac_sim/configs/experiments/kujiale_static_layout_draft_20260723-133702.yaml`，可继续在 GUI 中修改；
- 尺寸：四个方块为 `0.30 x 0.30 x 0.16 m`，两个长条为 `0.60 x 0.30 x 0.16 m`；
- 均位于原 `mapping_start` 周边的中心通行区域，周围保留可绕行空间；
- 障碍顶面低于 LiDAR 扫描高度，必须由 RGB-D、VoxelLayer 以及全局/局部 Costmap 识别；
- GUI 中只修改 Translate X/Y；运行时不覆盖手调位置。使用 `/experiment/obstacles/capture_layout` 导出 Map 坐标后可保存新的可微调基线并同步候选理论参考；只有用户确认冻结后，才将最后一次生成的参考作为正式批次输入；
- 在最终位置冻结前，不得运行 Pilot 或正式种子 `7201` 至 `7220`。

正式实验前的 Pilot 必须证明：

- `/scan` 没有直接检测该方块；
- RGB-D 深度数据包含有效障碍观测；
- 全局/局部 VoxelLayer 和 Costmap 成功形成障碍标记；
- 机器人确实绕行且没有接触；
- Reset 后相关 Costmap 残留能够在规定时间内清除。

### 3.2 动态场景

动态批次不放置低矮方块，设置两组高度为 `1.0 m`、LiDAR 和 RGB-D 均可见的慢速短距实体：

| ID | 触发路段 | Map 轨迹 | 尺寸 | 速度 | 启动延迟 |
| --- | --- | --- | --- | ---: | ---: |
| D1 `g1_g2_south_crossing` | G1 到 G2（G2 受理后） | `[1.15, -1.00] -> [0.45, -1.00]` | `0.40 x 0.40 x 1.00 m` | 0.10 m/s | `6.0 +/- 0.25 s` |
| D2 `g1_g2_north_crossing` | G1 到 G2（G2 受理后） | `[-0.20, 0.65] -> [0.50, 0.65]` | `0.40 x 0.40 x 1.00 m` | 0.10 m/s | `15.0 +/- 0.25 s` |

- G2（出生后的首个导航目标）被接受后才触发两组障碍；
- 延迟抖动由实验种子确定并可完全复现；
- 障碍完成短距轨迹后进入 `hold` 状态，保持终点位置；
- 每轮 Reset 必须恢复两组障碍的初始位置、速度、可见性和触发状态；
- 每轮两组障碍均须完成设定轨迹，并在 G1→G2 通道被传感器或 Costmap 观测；
- 漏触发、错误时序、或机器人没有出现减速/等待/重规划绕行中至少一种有效动态交互计为严格失败；
- 正式种子固定为 `7301` 至 `7320`。

### 3.3 成功率口径

每个批次同时报告：

1. `严格导航成功率 = 严格成功轮数 / 20`；
2. `物理无碰撞率 = 无任何物理接触轮数 / 20`。

严格成功必须同时满足：

- 5/5 航点全部成功；
- 所有航点的位置和朝向误差合格；
- 无 Isaac 物理碰撞事件；
- 无 TF、定位、传感器超时或 Nav2 Action 异常；
- 无单段或整轮超时；
- 障碍清除后不存在持续超过 15 s 的 Collision Monitor 安全锁停；
- 最终静止和最低闭环里程合格。

正式门槛同时检查严格成功率和物理无碰撞率：

- 静态批次均不低于 `19/20`；
- 动态批次均不低于 `18/20`。

首个目标下发前的环境故障不计入分母，并立即停止批次进行排查。首个目标一经下发，该轮结果必须计入分母，不允许选择性重跑。

## 4. 理论最优路径与指标计算

正式参考使用 footprint-aware SE(2) 状态格 A*，不使用会错误封闭窄门的单一圆形膨胀：

- Jackal footprint：`[[-0.230,-0.210],[0.255,-0.210],[0.255,0.210],[-0.230,0.210]]`；
- 安全 padding：`0.005 m`；
- Occupied 和 Unknown 均不可通行；
- 检查完整车体多边形以及运动原语的扫掠区域；
- 支持原地旋转和前进，报告长度只累计实际平移距离；
- 分段计算 S(G1) 到 G2、G2 到 G3，直至 G5 到 G1，再求闭环总长度；
- 静态参考地图加入低矮方块的真实占地多边形；
- 0.05 m 主结果与 0.025 m 局部细化结果的差异必须不高于 1%；
- 参考结果及地图、footprint、障碍、航点和算法哈希冻结到 `optimal_reference.json`。

每个成功静态实验计算：

```text
路径偏差 = abs(GT 闭环长度 - 理论最优闭环长度)
         / 理论最优闭环长度 * 100%
```

正式要求：

- 每个成功静态实验的路径偏差均不高于 20%；
- 输出平均值、P50、P95 和最大值；
- 输出每段路线偏差，整条闭环偏差作为正式验收门禁。

同时记录但不作为主门禁：

- 每段首次 `/plan` 长度；
- 后续重规划次数和路径长度；
- `/plan` 相对理论最优路径的偏差；
- GT 相对 `/plan` 的跟踪增量；
- `/optimal_trajectory` 和 `/transformed_global_plan`。

## 5. 配置、运行器与数据接口

### 5.1 场景与障碍配置

实验配置升级至 schema v2，并保持 schema v1 向后兼容：

- 路线航点增加稳定的 `id`，报告和障碍触发均按航点 ID 关联；

## 7. 执行、测试与最终验收

### 7.1 自动化测试

- schema v1/v2 兼容性；
- 静态及触发式动态障碍的解析、Reset、确定性抖动和 hold；
- 逐航点 GT 采样窗口不得跨 Reset 或混入航点间等待；
- 精确 footprint 碰撞检查和窄门通行；
- 每个航点均位于自由区、对应房间范围内并与整条路线连通；
- `19/20`、`18/20`、20% 路径偏差和重复种子等汇总边界；
- 图表数字、地图坐标和报告跨格式一致性。

### 7.2 Pilot

Pilot 数据单独保存，不得混入正式统计：

1. 1 次无新增障碍闭环，确认 5/5 航点、闭环连通和 GT 里程不少于 20 m；
2. 4 组低矮静态障碍，验证 RGB-D 专属检测链路、连续绕行和清除；
3. 3 次动态实验，验证 G2 后两组横穿通道、停住、有效交互和复位。

Pilot 全部通过后冻结代码、参数、障碍布局和理论参考。冻结后任何影响导航或指标的代码、参数、地图、路线或障碍变化，都必须重新开始正式 20+20 批次。

### 7.3 正式运行

- 每轮先执行完整 Reset；
- readiness gate 检查 Lifecycle Active、TF 连通、传感器新鲜、GT 起点误差不高于 `0.05 m/1 deg`、机器人静止和障碍状态正确；
- 依次执行静态 20 次和动态 20 次；
- 正式批次期间不得修改 Nav2、传感器、地图、路线或仿真参数；
- 全部运行结束后只使用自动汇总器生成最终报告。

### 7.4 最终通过条件

只有同时满足以下条件，才判定全屋长距离导航验收通过：

- 静态严格成功和物理无碰撞均至少 `19/20`；
- 动态严格成功和物理无碰撞均至少 `18/20`；
- 所有成功静态闭环路线的 GT 路径偏差均不高于 20%；
- 每轮结构化数据完整且校验通过；
- 全部失败均有时间线、轨迹证据和 MCAP；
- HTML、PDF、Markdown 和机器可读报告中的数值完全一致；
- 可视化报告中的所有房间航点采用统一展示和统计规则。
