# Kujiale 全屋长距离导航、避障测试与可视化报告方案

> 实施分支：`codex/kujiale-long-range-navigation-test`（基于 `codex/rgbd-local-costmap-fusion-plan`）
>
> 文档状态：已实现、Pilot 已通过、正式静态 20 次与动态 20 次已完成并通过验收
>
> 适用场景：`kujiale_0026_A_to_B_door_open.usd`

## 1. 实验目标与固定条件

在固定场景、地图、起点和路线下完成可复现的正式验收：

- 场景：`kujiale_0026_A_to_B_door_open.usd`；
- 地图：`warehouse_new`；
- 起点：`mapping_start`，Map 位姿 `[0.00, 0.00, 0 deg]`；
- 定位：Ideal Odometry / Ideal Localization；
- 导航配置：`rgbd_navigation`；
- 仿真：`physics_dt=1/60 s`、`RTF=1.0`；
- 静态避障：20 次，严格成功率和物理无碰撞率均须达到 `19/20=95%`；
- 动态避障：20 次，严格成功率和物理无碰撞率均须达到 `18/20=90%`；
- 每轮执行同一条覆盖所有房间并返回起点的闭环长路线；
- 每个成功静态实验的 Ground Truth 实际路线相对理论最优路线偏差均须不高于 `20%`；
- `/plan`、`/optimal_trajectory` 和 `/transformed_global_plan` 用于规划与跟踪诊断，不代替 Ground Truth 正式验收。

`ros2_ws/src/robot_description/rviz/navigation.rviz` 的导航视角配置与本方案一并纳入版本控制。正式报告记录 Git HEAD、工作区差异摘要以及所有配置和地图哈希。

## 2. 全屋闭环路线

每轮包含连续 8 个 `NavigateToPose` 动作，中途不重置机器人。所有房间航点采用相同的显示方式、成功条件和统计口径。

| 顺序 | 区域 | Map 目标 `[x, y, yaw]` | 栅格净空约值 |
| --- | --- | --- | ---: |
| S | 中央起点/起居区域 | `[0.00, 0.00, 0 deg]` | 1.20 m |
| G1 | 上方大房间 | `[0.80, 4.80, -135 deg]` | 0.90 m |
| G2 | 左上房间 | `[-3.45, 3.90, 0 deg]` | 0.35 m |
| G3 | 最左侧房间 | `[-4.05, 1.15, 0 deg]` | 0.36 m |
| G4 | 左侧厕所 | `[-3.25, -0.45, 0 deg]` | 0.55 m |
| G5 | 左下房间 | `[-2.50, -3.35, 90 deg]` | 0.46 m |
| G6 | 下方中部/右侧房间 | `[0.65, -4.25, -90 deg]` | 0.47 m |
| G7 | 最下方房间 | `[0.45, -5.35, 90 deg]` | 0.64 m |
| G8 | 返回起点 | `[0.00, 0.00, 0 deg]` | 1.20 m |

G4 对应 USD 坐标约 `[6.15, 0.25]`，位于语义节点 `/Root/Meshes/bathroom_1244` 范围内。其目标容差圆不会落到厕所外部或墙体上，因此实际要求是进入房间，而不是只到门口。

统一航点条件：

- 位置误差不高于 `0.25 m`；
- 朝向误差不高于 `10 deg`；
- 每段 Nav2 Action 必须返回 `SUCCEEDED`；
- 单段超时：静态 `180 s`、动态 `210 s`；
- 整轮超时：静态 `600 s`、动态 `720 s`；
- 最终静止时间不少于 `1 s`；
- 最终线速度不高于 `0.02 m/s`、角速度不高于 `0.05 rad/s`；
- 闭环 GT 实际里程不少于 `40 m`。

当前使用 0.25 m 圆形净空进行的离线连通性预检路线约为 `43.7 m`。该值只证明路线连通，正式理论值必须使用精确车体模型重新计算。

## 3. 障碍物与正式实验矩阵

### 3.1 静态场景

20 次静态实验使用同一个低矮实体障碍：

- ID：`rgbd_low_box`；
- Map 中心：`[-0.15, 0.70, 0.08]`；
- USD 中心约：`[3.05, -0.90, 0.08]`；
- 尺寸：`0.30 x 0.30 x 0.16 m`；
- 位于 S 到 G1 的通行区域，周围保留可绕行空间；
- 障碍顶面低于 LiDAR 扫描高度，必须由 RGB-D、VoxelLayer 以及全局/局部 Costmap 识别；
- 正式种子固定为 `7201` 至 `7220`。

正式实验前的 Pilot 必须证明：

- `/scan` 没有直接检测该方块；
- RGB-D 深度数据包含有效障碍观测；
- 全局/局部 VoxelLayer 和 Costmap 成功形成障碍标记；
- 机器人确实绕行且没有接触；
- Reset 后相关 Costmap 残留能够在规定时间内清除。

### 3.2 动态场景

动态批次不放置低矮方块，设置三个高度为 `1.0 m`、LiDAR 和 RGB-D 均可见的移动实体：

| ID | 触发路段 | Map 轨迹 | 尺寸 | 速度 | 启动延迟 |
| --- | --- | --- | --- | ---: | ---: |
| D1 `central_crossing` | S 到 G1 | `[-0.80, 0.65] -> [0.80, 0.65]` | `0.40 x 0.40 x 1.00 m` | 0.35 m/s | `0.40 +/- 0.15 s` |
| D2 `north_crossing` | G1 到 G2 | `[1.30, 4.35] -> [-0.10, 4.35]` | `0.40 x 0.40 x 1.00 m` | 0.30 m/s | `0.25 +/- 0.10 s` |
| D3 `south_crossing` | G5 到 G6 | `[-1.70, -3.20] -> [-2.60, -3.20]` | `0.35 x 0.35 x 1.00 m` | 0.25 m/s | `0.30 +/- 0.10 s` |

- 对应路段的导航目标被接受后触发障碍；
- 延迟抖动由实验种子确定并可完全复现；
- 障碍完成轨迹后进入 `retired` 状态，隐藏并关闭碰撞，避免永久堵住通道；
- 每轮 Reset 必须恢复三个障碍的初始位置、速度、可见性和触发状态；
- 每轮三个障碍均须完成至少 95% 的设定轨迹，并在对应路段被传感器或 Costmap 观测；
- 漏触发、错误时序或未形成有效交互计为严格失败；
- 正式种子固定为 `7301` 至 `7320`。

### 3.3 成功率口径

每个批次同时报告：

1. `严格导航成功率 = 严格成功轮数 / 20`；
2. `物理无碰撞率 = 无任何物理接触轮数 / 20`。

严格成功必须同时满足：

- 8/8 航点全部成功；
- 所有航点的位置和朝向误差合格；
- 无 Isaac 物理碰撞事件；
- 无 TF、定位、传感器超时或 Nav2 Action 异常；
- 无单段或整轮超时；
- 障碍清除后不存在持续超过 15 s 的 Collision Monitor 安全锁停；
- 最终静止和最低闭环里程合格。

正式门槛同时检查严格成功率和物理无碰撞率：

- 静态批次均不低于 `19/20`；
- 动态批次均不低于 `18/20`。

首个目标下发前的环境故障不计入分母，并立即停止批次进行排查。首个目标一经下发，该轮结果必须计入分母，不允许选择性重跑。

## 4. 理论最优路径与指标计算

正式参考使用 footprint-aware SE(2) 状态格 A*，不使用会错误封闭窄门的单一圆形膨胀：

- Jackal footprint：`[[-0.230,-0.210],[0.255,-0.210],[0.255,0.210],[-0.230,0.210]]`；
- 安全 padding：`0.005 m`；
- Occupied 和 Unknown 均不可通行；
- 检查完整车体多边形以及运动原语的扫掠区域；
- 支持原地旋转和前进，报告长度只累计实际平移距离；
- 分段计算 S 到 G1、G1 到 G2，直至 G7 到 G8，再求闭环总长度；
- 静态参考地图加入低矮方块的真实占地多边形；
- 0.05 m 主结果与 0.025 m 局部细化结果的差异必须不高于 1%；
- 参考结果及地图、footprint、障碍、航点和算法哈希冻结到 `optimal_reference.json`。

每个成功静态实验计算：

```text
路径偏差 = abs(GT 闭环长度 - 理论最优闭环长度)
         / 理论最优闭环长度 * 100%
```

正式要求：

- 每个成功静态实验的路径偏差均不高于 20%；
- 输出平均值、P50、P95 和最大值；
- 输出每段路线偏差，整条闭环偏差作为正式验收门禁。

同时记录但不作为主门禁：

- 每段首次 `/plan` 长度；
- 后续重规划次数和路径长度；
- `/plan` 相对理论最优路径的偏差；
- GT 相对 `/plan` 的跟踪增量；
- `/optimal_trajectory` 和 `/transformed_global_plan`。

## 5. 配置、运行器与数据接口

### 5.1 场景与障碍配置

实验配置升级至 schema v2，并保持 schema v1 向后兼容：

- 路线航点增加稳定的 `id`，报告和障碍触发均按航点 ID 关联；
- 物理障碍支持 `stationary` 和 `linear` 两种模式；
- 动态障碍支持 `trigger_group`、确定性延迟抖动和 `post_motion: retire`；
- schema v2 允许障碍直接使用 Map 坐标，由 `mapping_start` 标定变换到 USD；
- 启动时校验场景、地图、出生点标定和物理障碍配置哈希。

运行时提供：

- `/experiment/obstacles/<group>/trigger`；
- `/experiment/obstacles/reset`；
- `/experiment/obstacles/state`。

Reset、触发、开始运动、到达终点和 retire 均写入带仿真时间戳的事件记录。

### 5.2 每轮完整数据

每轮至少保存：

- `run_manifest.json`：分支、提交、dirty diff 哈希、硬件、驱动、Isaac/ROS 版本、地图和配置哈希、种子及时间；
- `events.jsonl`：Reset、Action、航点、恢复、碰撞、Collision Monitor、障碍触发和故障时间线；
- `ground_truth.csv.gz`；
- `odom.csv.gz`；
- `cmd_vel.csv.gz`；
- `obstacles.csv.gz`；
- `leg_metrics.csv`；
- `run_summary.json`；
- 轨迹图、Costmap、RGB-D 检测证据和失败截图；
- 文件级 SHA-256 校验清单。

每段数据记录 GT 长度、耗时、目标误差、重规划次数、停止时间、恢复次数、最小障碍距离和传感器检测证据。

Zstd 压缩 MCAP 保留范围：

- 全部失败实验；
- 预先指定的静态种子 `7201`、`7210`、`7220`；
- 预先指定的动态种子 `7301`、`7310`、`7320`。

其他成功实验仍保留完整结构化数据和日志。MCAP 至少覆盖 GT/Odom、TF、速度、Action、全局与局部路径、Costmap/VoxelGrid、Scan、RGB-D、碰撞以及障碍状态。

## 6. 最终可视化报告

最终交付一个无需服务器、可直接打开的自包含中文 HTML 仪表盘，并同步导出 PDF、Markdown、PNG、CSV 和 JSON：

```text

|-- index.html
|-- report.pdf
|-- report.md
|-- benchmark.json
|-- benchmark.csv
|-- data_dictionary.md

```

`campaign_id` 使用正式批次启动时的 `YYYYMMDD-HHMMSS`。`index.html` 由统一的 `benchmark.json` 自动生成，验收结论不得手工填写。

- 静态严格成功次数、百分比和 95% Wilson 区间；

- 静态、动态物理无碰撞率；
- 最大路径偏差；
- 总实验时间、总里程和碰撞总数；
- 明确显示 95%、90% 和 20% 三条验收门槛。

## 7. 执行、测试与最终验收

### 7.1 自动化测试

- schema v1/v2 兼容性；
- 静态及触发式动态障碍的解析、Reset、确定性抖动和 retire；
- 逐航点 GT 采样窗口不得跨 Reset 或混入航点间等待；
- 精确 footprint 碰撞检查和窄门通行；
- 每个航点均位于自由区、对应房间范围内并与整条路线连通；
- `19/20`、`18/20`、20% 路径偏差和重复种子等汇总边界；
- 图表数字、地图坐标和报告跨格式一致性。

### 7.2 Pilot

Pilot 数据单独保存，不得混入正式统计：

1. 1 次无新增障碍闭环，确认 8/8 航点、闭环连通和 GT 里程不少于 40 m；
2. 3 次低矮静态障碍，验证 RGB-D 专属检测链路、绕行和清除；
3. 3 次动态实验，验证三个分段触发、有效交互和复位。

Pilot 全部通过后冻结代码、参数、障碍布局和理论参考。冻结后任何影响导航或指标的代码、参数、地图、路线或障碍变化，都必须重新开始正式 20+20 批次。

### 7.3 正式运行

- 每轮先执行完整 Reset；
- readiness gate 检查 Lifecycle Active、TF 连通、传感器新鲜、GT 起点误差不高于 `0.05 m/1 deg`、机器人静止和障碍状态正确；
- 依次执行静态 20 次和动态 20 次；
- 正式批次期间不得修改 Nav2、传感器、地图、路线或仿真参数；
- 全部运行结束后只使用自动汇总器生成最终报告。

### 7.4 最终通过条件

只有同时满足以下条件，才判定全屋长距离导航验收通过：

- 静态严格成功和物理无碰撞均至少 `19/20`；
- 动态严格成功和物理无碰撞均至少 `18/20`；
- 所有成功静态闭环路线的 GT 路径偏差均不高于 20%；
- 每轮结构化数据完整且校验通过；
- 全部失败均有时间线、轨迹证据和 MCAP；
- HTML、PDF、Markdown 和机器可读报告中的数值完全一致；
- 可视化报告中的所有房间航点采用统一展示和统计规则。
